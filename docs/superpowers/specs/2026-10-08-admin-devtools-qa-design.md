# 어드민 QA 도구 설계 (묶음 2): 실시간 이벤트 스트림과 이벤트 사전

- 작성일: 2026-10-08
- 브랜치: `feat/admin-devtools-qa`
- 상태: 구현됨(2026-10-08), 브랜치 전체 리뷰 반영. 실제 호출 측정(§8)과 브라우저 화면 확인은 아직 하지 않음. 주기 상수는 기본값(5초)

## 1. 목표

어드민의 `개발자 도구` 그룹에 QA 때 쓰는 화면 두 개를 넣는다.

- **실시간 이벤트 스트림**: 방금 앱에서 쏜 이벤트가 GA에 들어왔는지 바로 확인한다. GA DebugView를 열지 않아도 된다.
- **이벤트 사전**: 이벤트의 뜻과 파라미터를 찾아보고, 정의와 실제 수집이 어긋난 곳을 찾는다.

쓰는 사람은 QA 중인 개발자와 비개발 직군(기획, 디자인, 마케팅)이다.

### 성공 기준

- 페이지 폴더 두 개를 추가하는 것만으로 사이드바, 모바일 메뉴, `⌘K`, URL에 반영된다. 기반의 "고치지 않는 파일" 7개는 고치지 않는다.
- 스트림 화면을 켜 둔 채 잊어도 GA quota가 바닥나지 않는다.
- 앱 팀의 이벤트 정의 문서가 나중에 오면 카탈로그 파일 하나만 채워서 사전이 완성된다.

### 판단 기준

설계 선택은 확장성, 쓰는 사람의 편의, 보기 좋음 순으로 따진다. 구현이 쉬운지는 기준이 아니다.

### 제약

- OAuth scope는 `analytics.readonly` 그대로다. CSP도 그대로다(`analyticsdata.googleapis.com`은 이미 허용돼 있다).
- 서버와 공유 저장소가 없다. 사전을 화면에서 편집해 저장할 수 없다.
- 기존 대시보드 스펙(`2026-09-29-ga-admin-dashboard-design.md`)의 보안 규칙을 지킨다. 토큰은 메모리에만 둔다.
- 메뉴 규칙은 기반 스펙(`2026-10-07-admin-menu-registry-design.md`)을 따른다. `devtools` 그룹의 `order`는 200~290을 쓴다.

### 확인한 사실 (Google 문서, 2026-10-08)

- Realtime API가 지원하는 측정기준: `appVersion`, `eventName`, `minutesAgo`, `platform`, `streamId`, `unifiedScreenName` 등. 측정항목은 `activeUsers`, `eventCount`, `keyEvents`, `screenPageViews`다.
- Realtime API는 이벤트 범위 커스텀 측정기준을 지원하지 않는다. 그래서 스트림에서는 이벤트 파라미터 값을 볼 수 없다.
- Realtime API는 사용자 범위 커스텀 측정기준(`customUser:<이름>`)과 `dimensionFilter`를 지원한다. 기본 측정기준에는 기기나 사용자를 가리는 것이 없다. 그래서 앱이 QA용 사용자 속성을 보내지 않는 한, 여러 명이 동시에 QA하면 이벤트가 섞인다.
- 표준 속성은 최근 30분까지만 조회된다(`startMinutesAgo` 최대 29).
- `runRealtimeReport`의 `limit`은 기본 10,000, 최대 250,000이다. `offset`은 없다.
- `runRealtimeReport`도 `returnPropertyQuota`를 받는다. 돌려주는 값은 realtime 한도의 상태다.
- 응답의 quota 항목(`tokensPerDay` 등)에서 `consumed`는 **이 요청 하나가 쓴 양**이고 `remaining`은 요청 뒤에 남은 양이다. 누적 사용량이 아니다.
- 표준 속성의 realtime 한도: 하루 200,000 토큰, 시간당 40,000 토큰, 프로젝트·속성당 시간당 14,000 토큰, 동시 요청 10개, 시간당 서버 오류 10회. 일반 조회(core) 한도와는 별도다.
- 요청 한 번의 토큰 비용은 행 수, 측정기준 수, 데이터 양에 따라 달라진다. 문서에 고정 값이 없다.
- `GET properties/{id}/metadata`는 `analytics.readonly`로 호출된다. 속성에 등록한 이벤트 파라미터는 `customEvent:<이름>`으로 나온다. 커스텀 측정기준은 `dimensions[]`에, 커스텀 측정항목은 `metrics[]`에 들어 있다.

### 확인하지 못한 것

구현 중 실제 호출로 확인한다(§8).

- 앱이 이벤트를 쏜 뒤 Realtime API에 반영되기까지 걸리는 시간
- 스트림 요청 한 번의 토큰 비용
- 이 속성의 metadata에 `customEvent:` 항목이 실제로 있는지
- Google 로그인 토큰의 실제 수명(보통 1시간)

## 2. 실시간 이벤트 스트림

### 메뉴

| 필드 | 값 |
|------|----|
| `id` | `event-stream` |
| `group` | `devtools` |
| `order` | 210 |
| `label` | 실시간 이벤트 |
| `description` | 방금 들어온 이벤트를 바로 확인해요 |
| `keywords` | `QA`, `디버그`, `debugview`, `realtime`, `스트림` |
| `usesPeriod` | `false` |
| `usesGa` | `false` |

`usesGa`를 `false`로 두는 이유: 셸은 이 값을 푸터의 "오늘 조회 가능량" 배지를 보여 줄지 정하는 데만 쓴다. 그 배지는 일반 조회 한도다. 이 화면은 realtime 한도만 쓰므로, 배지를 보여 주면 "98% 남음" 옆에 "실시간 조회 한도가 거의 남지 않았어요"가 함께 나올 수 있다. 이 화면의 한도 상태는 상태 줄이 알린다.

### 조회

갱신 한 번에 `runRealtimeReport` 요청 하나를 보낸다.

- 측정기준: `eventName`, `minutesAgo`, `platform`, `appVersion`
- 측정항목: `eventCount`
- 범위: `minuteRanges: [{ startMinutesAgo: 29, endMinutesAgo: 0 }]`
- 정렬: `minutesAgo` 오름차순(숫자 정렬)
- `limit: 250000`, `returnPropertyQuota: true`

플랫폼과 앱 버전을 측정기준으로 함께 받는 이유는, 필터를 바꿀 때 다시 요청하지 않기 위해서다. 받은 행을 화면에서 걸러서 합친다.

행 수는 이벤트 수 × 30분 × 플랫폼 수 × 앱 버전 수까지 늘 수 있다. 응답의 `rowCount`가 받은 행 수보다 크면 일부가 잘린 것이다. `minutesAgo` 오름차순으로 받으므로 잘리는 쪽은 오래된 분이다. 이때 표 아래에 "이벤트가 많아서 오래된 기록 일부가 빠졌어요. 30분 횟수가 실제보다 적을 수 있어요."라고 알린다.

react-query 설정은 기본값을 쓰지 않고 아래로 둔다. 기본값(`staleTime` 10분, 실패 시 재시도 1회)은 이 화면과 맞지 않는다.

- `queryKey: ['event-stream']`, `staleTime: 0`, `gcTime: 0`, `retry: false`, `refetchOnWindowFocus: false`
- 재시도를 끄는 이유: 재시도는 주기 정책 밖에서 요청을 하나 더 보내고, 시간당 서버 오류 10회 한도를 깎는다. 실패 뒤의 다음 시도는 주기 정책이 정한다.
- `gcTime`을 0으로 두는 이유: 메뉴를 떠났다 돌아왔을 때 몇 분 전 데이터가 방금 받은 것처럼 보이면 안 된다.
- 주기는 `refetchInterval`에 주기 정책의 결과를 넘겨서 건다.

**상태 줄**

- 지금 주기와, 느려졌거나 멈췄다면 그 이유를 한 문장으로 보여 준다(주기 정책의 표).
- 마지막 갱신 시각은 서울 시간 `HH:mm:ss`로 쓴다.
- `일시정지`를 누르면 자동 갱신이 멈추고 버튼이 `다시 시작`으로 바뀐다. 표를 고정해 놓고 읽을 때 쓴다.
- `지금 새로고침`은 일시정지 중에도, 한도 때문에 멈춘 중에도 한 번 조회한다.

**필터**

- 이벤트 검색: 원래 이름과 한글 라벨 둘 다에서 찾는다. 대소문자를 가리지 않는다.
- 플랫폼, 앱 버전: 최근 30분 응답에 나온 값만 고를 수 있다. URL에 있는 값이 응답에 없으면 그 값을 선택된 상태로 목록에 남겨 둔다. 그래야 링크로 받은 필터가 조용히 풀리지 않는다.
- GA가 주는 빈 값과 `(not set)`은 파싱할 때 `(not set)` 하나로 합친다. 화면에는 `알 수 없음`으로 보여 주고, URL에는 `(not set)`을 쓴다.

**표**

| 열 | 내용 |
|----|------|
| 지켜보기 | 별 모양 토글 버튼. 켠 이벤트는 표 맨 위에 고정된다. |
| 이벤트 | 카탈로그에 있으면 한글 라벨을 크게, 원래 이름을 작게 쓴다. 없으면 원래 이름과 `사전에 없음` 태그를 쓴다. |
| 방금 | `minutesAgo`가 0인 횟수. 지금 진행 중인 1분이다. |
| 5분 | `minutesAgo` 0~4의 합 |
| 30분 | 전체 합 |
| 30분 추이 | 1분 단위 막대 30개. 장식이므로 `aria-hidden`이다. 값은 숫자 열이 전한다. |

- 정렬: 지켜보는 이벤트가 먼저, 그 안에서와 나머지는 30분 합계가 큰 순서다. 같으면 이름 순이다. 갱신마다 행이 뛰어다니지 않도록 `방금` 값으로는 정렬하지 않는다.
- 지켜보는 이벤트가 최근 30분에 한 번도 없으면 0으로 채운 행을 보여 준다. "아직 안 들어옴"을 확인하는 것이 QA의 목적이기 때문이다.
- 지켜보는 행은 검색어와 상관없이 항상 보인다. 숫자는 플랫폼과 앱 버전 필터를 따른다.
- 행의 React key는 이벤트 이름이다. 순서가 바뀌어도 포커스와 강조 상태가 그 행에 남는다.

**변화 강조**

직전 갱신과 비교해서 표시한다. 색만으로 전하지 않는다.

- 직전에 없던 이벤트: `새로 들어옴` 태그
- `5분` 값이 직전 갱신보다 늘어난 이벤트: `▲ +n` 텍스트. `n`은 늘어난 횟수다. 줄어든 것은 표시하지 않는다. 시간이 지나 오래된 1분이 창에서 빠진 것일 뿐이기 때문이다.
- 강조에는 "8초 전"처럼 생긴 뒤로 지난 시간을 함께 쓴다. 강조는 생긴 뒤 60초 동안 남는다. 휴대폰에서 이벤트를 보내고 화면으로 눈을 돌리는 사이에 사라지면 안 된다. 60초 안에 같은 이벤트가 또 늘면 `n`을 더하고 시간을 다시 잰다. 유지 시간은 `config.ts`의 상수다.
- 비교는 직전 갱신의 원본 행을 **지금 필터로 다시 합쳐서** 한다. 필터를 바꾼 것만으로 `▲`가 생기지 않는다.
- 비교 기준이 없는 조회에는 강조하지 않는다. 화면에 들어온 뒤 첫 조회, 그리고 직전 갱신이 90초보다 오래된 조회(일시정지나 느린 주기 뒤)가 해당한다. 오래 벌어진 사이의 변화를 "방금"으로 보여 주면 틀리다.
- 일시정지 중에 `지금 새로고침`을 누르면 화면에 있던 표가 비교 기준이다. 위의 90초 규칙을 그대로 따른다.
- 한계: 새 이벤트가 들어온 바로 그 갱신에서 5분 전의 이벤트가 같은 수만큼 창에서 빠지면 `▲`가 뜨지 않는다. 숫자 열은 맞게 나온다.
- 지켜보는 이벤트에 변화가 있을 때만 `aria-live="polite"` 영역에 "화면 조회 3번 더 들어왔어요"처럼 알린다. 모든 변화를 읽어 주면 5초마다 말이 끊기지 않는다. 알리는 숫자는 그 이벤트를 마지막으로 알린 뒤에 늘어난 횟수다(화면의 `▲ +n`은 60초 동안 쌓인 값이라 서로 다를 수 있다). 같은 문장을 다시 알릴 때도 읽히도록 알림마다 새 요소로 그린다.
- 배경 강조 애니메이션은 `prefers-reduced-motion`에서 끈다.

**사전으로 가기**

`사전에 없음` 태그 옆에 `사전에서 보기` 버튼을 둔다. `useNav().setMenu('event-dictionary', { event: 이름 })`으로 이동한다(§5). 사전은 그 이벤트를 펼친 채로 열린다.

### URL 상태

`usePageParam`으로 둔다. 이 URL을 팀원에게 넘기면 같은 필터로 열린다.

| key | 값 | 예 |
|-----|----|----|
| `q` | 검색어 | `q=purchase` |
| `platform` | 플랫폼 값 | `platform=iOS` |
| `ver` | 앱 버전 값 | `ver=1.4.0` |
| `watch` | 지켜보는 이벤트 이름을 쉼표로 이은 값 | `watch=screen_view,purchase_done` |

- 검색창은 입력 값을 자기 상태로 들고 있다가 300ms 동안 입력이 없을 때, 포커스를 잃을 때, Enter를 누를 때 `q`에 쓴다. 한글 조합 중에는 쓰지 않는다. 글자마다 `history.replaceState`를 부르면 브라우저의 호출 제한에 걸릴 수 있다. 뒤로 가기로 URL이 바뀌면 검색창이 그 값을 다시 읽는다.
- 필터를 바꿔도 방문 기록에 새 항목이 생기지 않는다(기반의 동작). 뒤로 가기는 필터를 하나씩 되돌리지 않고 이전 메뉴로 간다.
- 일시정지 여부는 URL에 두지 않는다. 링크를 받은 사람의 화면이 멈춘 채로 열리면 고장으로 보인다.

### 주기 정책

다음 갱신까지의 시간을 정하는 순수 함수 하나로 둔다.

```ts
type PollInput = {
  quotaShare: number | null     // 남은 realtime 한도의 비율(0~1). 첫 응답 전에는 null
  visible: boolean              // 탭이 보이는지
  paused: boolean               // 사용자가 일시정지했는지
  idleMs: number                // 마지막 조작 뒤로 지난 시간
  failures: number              // 연속 실패 횟수(네트워크, 서버, 알 수 없는 오류)
  blocked: 'quota' | 'bad_request' | null   // 자동으로 풀리지 않는 직전 오류
}
type PollDecision = { intervalMs: number | null; reason: PollReason }
function decidePoll(input: PollInput): PollDecision
```

`intervalMs`가 `null`이면 자동 갱신을 멈춘다. 먼저 멈춤 조건을 위에서부터 본다.

| 멈춤 조건 | 상태 줄 문구 |
|-----------|--------------|
| 일시정지 | 일시정지했어요 |
| 탭이 가려짐 | (보이지 않음) |
| quota 오류를 받음 | 실시간 조회 한도를 다 써서 자동 갱신을 멈췄어요. 한 시간쯤 뒤에 다시 시도해 주세요. |
| 요청이 잘못됐다는 오류를 받음 | 불러오지 못했어요. 자동 갱신을 멈췄어요. |
| 남은 한도 5% 미만 | 실시간 조회 한도가 거의 남지 않아서 자동 갱신을 멈췄어요 |

멈춤 조건에 걸리지 않으면 **평소 주기**를 위에서부터 먼저 맞는 줄로 정한다.

| 조건 | 평소 주기 | 상태 줄 문구 |
|------|-----------|--------------|
| 남은 한도 20% 미만 | 60초 | 실시간 조회 한도가 얼마 남지 않아서 1분마다 갱신해요 |
| 10분 넘게 조작 없음 | 60초 | 한동안 조작이 없어서 1분마다 갱신해요 |
| 남은 한도 50% 미만 | 15초 | 실시간 조회 한도를 아끼려고 15초마다 갱신해요 |
| 그 밖 | 5초 | 5초마다 갱신 중 |

연속 실패가 있으면 `max(평소 주기, 5초 × 2^실패 횟수)`를 쓰고 60초를 넘기지 않는다. 문구는 "불러오지 못해서 다시 시도하고 있어요"다. 실패했다고 평소보다 빨라지는 일은 없다.

세부 규칙:

- **남은 한도**는 `tokensPerHour`, `tokensPerProjectPerHour`, `tokensPerDay` 각각의 `remaining / 한도` 중 가장 작은 값이다. 한도는 `config.ts`의 상수다(40,000 / 14,000 / 200,000). `consumed`는 이 요청 하나가 쓴 양이라서 분모로 쓸 수 없다. 응답에 없는 항목은 건너뛴다. 셋 다 없으면 1로 본다.
- **실패로 세는 오류**는 `network`와 `server`, 그리고 종류를 알 수 없는 오류(응답 본문을 읽지 못한 경우 등)다. 알 수 없는 오류도 실패로 세어 주기를 늦춘다. 성공하면 0으로 돌아간다. `auth`와 `forbidden`은 셸이 로그인 화면으로 바꾸므로 이 화면이 다루지 않는다.
- **조작**은 `document`에서 받는 `pointerdown`, `keydown`, `wheel`, `scroll`이다. 포인터를 움직이기만 한 것은 세지 않는다. 리스너는 훅 안에서 붙이고 화면을 떠날 때 뗀다.
- 조작이 없어 느려진 상태에서 조작이 다시 생기면, 화면의 데이터가 5초보다 오래됐을 때 바로 한 번 조회한다.
- 탭이 다시 보일 때는 멈춤 조건에 걸리지 않은 경우에만 바로 한 번 조회한다. 일시정지한 표는 탭을 오가도 그대로다.
- `지금 새로고침`이 성공하면 quota 오류와 요청 오류로 멈춘 상태가 풀린다.
- `다시 시작`을 누르면 바로 한 번 조회한다.
- 플랫폼이나 앱 버전 필터를 바꾸면 남아 있던 강조를 지운다. 다른 필터에서 생긴 `▲ +n`이 지금 숫자 옆에 남으면 틀리다.
- 주기, 기준 비율, 한도, 유지 시간은 모두 페이지 폴더의 `config.ts`에 상수로 둔다. §8의 측정 결과로 조정한다.

시간당 한도는 한 시간마다 회복되므로, 느려진 주기는 사람이 손대지 않아도 원래대로 돌아온다.

**로그인 만료**

토큰이 만료되면 셸이 화면 전체를 "로그인이 만료됐어요"로 바꾸고 조회가 멈춘다. 그래서 잊고 켜 둔 탭의 조회는 토큰 수명(보통 1시간)을 넘지 않는다. 다시 로그인하면 URL에 있는 검색어, 필터, 지켜보는 이벤트는 돌아온다. 표, 일시정지 여부, 비교 기준은 돌아오지 않고, 첫 조회에는 강조가 없다.

### 상태별 화면

`CardState`는 첫 조회 중과 첫 조회 실패에만 쓴다. `CardState`의 빈 상태 문구는 "이 기간에는 데이터가 없어요"로 고정돼 있고 버튼 자리가 없다. 그래서 `isEmpty={false}`로 넘기고 빈 상태는 이 화면이 직접 그린다.

- 첫 조회 중: 카드 안 스켈레톤
- 첫 조회 실패: 오류 문구와 `다시 시도`. quota 오류면 `CardState`의 "오늘 조회 한도" 문구 대신 주기 정책 표의 실시간 한도 문구를 쓴다.
- 최근 30분에 이벤트가 없음: "최근 30분 동안 들어온 이벤트가 없어요. 앱에서 이벤트를 보내면 여기에 나타나요."
- 필터 결과가 없음: "조건에 맞는 이벤트가 없어요"와 `필터 지우기` 버튼. `필터 지우기`는 `q`, `platform`, `ver`를 지우고 `watch`는 남긴다.
- 지켜보는 이벤트가 있으면 위 두 빈 상태는 지켜보는 행 아래에 나온다. 지켜보지 않는 행이 없다는 뜻이다.
- 검색어와 필터가 모두 비어 있으면 "조건에 맞는 이벤트가 없어요"는 보여 주지 않는다. 최근 30분의 이벤트를 전부 지켜보고 있을 때 아무것도 지우지 못하는 `필터 지우기`가 나오면 안 된다.
- 갱신 실패: 마지막으로 받은 표를 그대로 두고 상태 줄에만 알린다.

### 모바일과 접근성

- 960px 미만에서는 `30분 추이` 열을 빼고, 태그와 강조를 이벤트 이름 아래 줄로 내린다. 이벤트 칸은 줄바꿈을 허용한다. 숫자 세 열이 가로 스크롤 없이 보여야 한다.
- 별 버튼, `사전에서 보기`, 상태 줄의 버튼은 누르는 영역이 44px(`--adm-hit`) 이상이다.
- 별 버튼은 `aria-pressed`와 "screen_view 지켜보기" 같은 이름을 가진다. 눌러서 행이 맨 위로 옮겨져도 포커스는 그 버튼에 남는다.
- 검색창과 두 선택 상자에는 보이는 라벨을 둔다. 입력 글자 크기는 16px(`--adm-fs-md`) 이상이다. 그보다 작으면 iOS에서 화면이 확대된다.
- 상태 줄에서 주기와 이유를 적는 문장은 `role="status"`다. 느려지거나 멈출 때 한 번 읽힌다. "마지막 갱신" 시각은 그 영역 밖에 둔다. 5초마다 읽히면 안 된다.

### 메뉴

| 필드 | 값 |
|------|----|
| `id` | `event-dictionary` |
| `group` | `devtools` |
| `order` | 220 |
| `label` | 이벤트 사전 |
| `description` | 이벤트의 뜻과 파라미터를 찾아봐요 |
| `keywords` | `이벤트`, `파라미터`, `정의`, `미등록`, `dictionary` |
| `usesPeriod` | `true` |
| `usesGa` | `true` |

기간 필터를 쓰는 이유는 "이 기간에 들어왔는가"가 사전의 핵심 판정이기 때문이다.

### 원본 네 가지

| 원본 | 주는 것 | 어디서 | react-query |
|------|---------|--------|-------------|
| 카탈로그 | 이벤트 이름, 한글 라벨, 설명, 파라미터, 구분, 대상 플랫폼 | 레포 파일 `src/admin/ga/eventCatalog.ts` (§4) | 없음 |
| 기간 관측 | 고른 기간에 들어온 이벤트, 횟수, 사람 수, 플랫폼별 횟수 | `runReport` | `['event-dictionary', 'observed', ranges]`, 기본 설정 |
| 오늘 관측 | 최근 30분에 들어온 이벤트와 플랫폼 | `runRealtimeReport` | `['event-dictionary', 'recent']`, `staleTime` 60초 |
| GA metadata | 속성에 등록된 이벤트 파라미터 | `GET metadata` | `['event-dictionary', 'metadata']`, `staleTime`과 `gcTime` 무한 |

**기간 관측** 요청:

- 측정기준: `eventName`, `platform`
- 측정항목: `eventCount`, `totalUsers`
- 기간: 현재 기간 하나(직전 기간과 비교하지 않는다)
- `limit: 10000`

**오늘 관측**이 필요한 이유: 셸의 기간은 항상 어제까지다. 오늘 처음 넣은 이벤트는 기간 관측에 없다. 그러면 스트림에서 방금 본 이벤트를 사전에서 찾을 수 없고, 오늘 구현한 이벤트가 `안 들어옴`으로 남는다. 요청은 측정기준 `eventName`, `platform`과 측정항목 `eventCount`이고, 화면을 열 때 한 번 조회한다. 주기적으로 갱신하지 않는다.

**metadata**는 `dimensions[]`와 `metrics[]` 양쪽에서 `apiName`이 `customEvent:`로 시작하는 항목을 고른다. 숫자 파라미터는 커스텀 측정항목으로 등록되므로 `metrics[]`를 빼면 놓친다.

### 이벤트 상태

카탈로그, 기간 관측, 오늘 관측을 이벤트 이름으로 합친 뒤 상태를 하나 매긴다. "들어옴"은 기간 관측이나 오늘 관측 중 한 곳에라도 있다는 뜻이다. 위에서부터 먼저 맞는 것을 쓴다.

| 상태 | 조건 | 뜻 |
|------|------|-----|
| 사전에 없음 | 들어왔는데 카탈로그에 없다 | 정의 없이 수집되고 있다. 오타이거나 문서에서 빠진 이벤트다. |
| 안 들어옴 | 카탈로그에 앱 정의 이벤트로 있는데 들어오지 않았다 | 구현이 빠졌거나 이름이 다르다. |
| 일부 플랫폼만 | 카탈로그의 대상 플랫폼 중 들어오지 않은 플랫폼이 있다 | 한쪽 플랫폼 구현이 빠졌다. |
| 설명 없음 | 카탈로그에 있지만 설명이 비어 있다 | 문서를 채워야 한다. |
| 정상 | 그 밖 | |

- 카탈로그에서 `platforms`를 생략한 이벤트의 대상 플랫폼은 `['Android', 'iOS']`다. 이 값은 카탈로그 파일의 상수다.
- 자동 수집 이벤트(`kind: 'auto'`)는 `안 들어옴`과 `일부 플랫폼만`으로 판정하지 않는다. 앱 팀이 구현하는 이벤트가 아니고, `app_remove`처럼 한 플랫폼에서만 오는 것이 정상인 이벤트가 있다.
- 기간 관측이 아직 끝나지 않았거나 실패했으면 `사전에 없음`, `안 들어옴`, `일부 플랫폼만`은 판정하지 않는다. 받지 못한 것을 0건으로 읽으면 전부 문제로 보인다. 이때 카탈로그의 이벤트는 `설명 없음`이나 `정상`으로만 보인다.
- 오늘 관측만 실패했으면 기간 관측만으로 판정하고, 표 위에 "오늘 들어온 이벤트는 확인하지 못했어요"를 한 줄 보여 준다.
- 오늘 관측이 끝나기 전(성공이든 실패든)에는 판정하지 않는다. 기간 관측만 먼저 오면 오늘 넣은 이벤트가 `안 들어옴`으로 떴다가 바뀐다.
- 기간 관측을 한 번 받은 뒤 다시 조회가 실패하면 받아 둔 값을 그대로 쓴다. 화면에 있던 횟수가 사라지면 안 된다. 실패는 그 기간의 값이 하나도 없을 때만 알린다.

**상태 버튼**

- 상태별 개수를 보여 주고, 누르면 그 상태만 거른다. 하나만 고를 수 있고 `전체`가 기본이다. 고른 버튼을 다시 누르면 `전체`로 돌아간다.
- `aria-pressed`를 쓰는 토글 버튼 묶음이다. 개수가 0인 버튼도 자리를 지킨다. 버튼이 사라지면 문제가 없다는 사실이 보이지 않는다.
- 기간 관측을 아직 받지 못했으면 `사전에 없음`, `안 들어옴`, `일부 플랫폼만`의 개수 자리에 `—`를 쓴다. 0은 "문제 없음"으로 읽힌다. 이 상태에서 그 버튼을 고르면(링크로 들어온 경우 포함) 목록 자리에 조회 중이면 스켈레톤을, 실패했으면 오류와 `다시 시도`를 보여 준다.

**판정 기준 줄**

상태 버튼 아래에 어느 기간으로 판정했는지 적는다. 기간은 어제까지이고, 오늘은 최근 30분만 본다는 사실을 숨기지 않는다.

**검색**

이벤트 이름, 한글 라벨, 설명, 파라미터 이름에서 찾는다. `q`를 쓰는 방식은 스트림의 검색창과 같다(300ms 뒤, 포커스를 잃을 때, Enter).

**이벤트 표**

| 열 | 내용 |
|----|------|
| 이벤트 | 펼치기 버튼, 한글 라벨, 원래 이름. 오늘 관측에만 있으면 `오늘 들어옴` 태그 |
| 구분 | `자동 수집`, `앱 정의`. 카탈로그에 없으면 `—` |
| 횟수 | 기간 안의 `eventCount`. 조회 전이면 스켈레톤 |
| 상태 | 상태 태그. 정상은 태그 없이 `정상` 텍스트 |

- 정렬: 문제가 있는 상태(사전에 없음, 안 들어옴, 일부 플랫폼만, 설명 없음)가 먼저, 그 안에서는 횟수가 큰 순서, 같으면 이름 순이다.
- 행 전체가 아니라 펼치기 버튼이 `aria-expanded`와 `aria-controls`를 가진다.

**펼친 내용**

- 설명. 비어 있으면 "아직 설명이 없어요"
- 파라미터 표: 이름, 타입, 설명. 파라미터가 GA metadata에 `customEvent:<이름>`으로 있으면 `GA 등록됨` 태그를 붙인다. 등록되지 않은 파라미터는 GA 보고서에서 조회할 수 없다는 뜻이다.
- 플랫폼별 횟수와 사람 수(기간), 최근 30분의 플랫폼별 횟수
- `사전에 없음`인 이벤트에는 `카탈로그 항목 복사` 버튼을 둔다. 누르면 `eventCatalog.ts`에 붙여 넣을 항목을 클립보드에 넣고, 버튼 글자가 2초 동안 `복사했어요`로 바뀐다. 클립보드를 쓸 수 없으면 코드를 선택할 수 있는 글상자로 보여 준다.

복사되는 코드:

```ts
{ name: 'purchase_done', label: '', description: '', kind: 'app', params: [] },
```

**GA에 등록된 파라미터 카드**

metadata의 `customEvent:` 항목을 표로 보여 준다. 열은 파라미터 이름, GA에 적힌 표시 이름, 종류(`측정기준` 또는 `측정항목`), 설명이다. GA는 어떤 파라미터가 어떤 이벤트에 속하는지 알려 주지 않으므로 이벤트 표와 따로 둔다. 카탈로그의 어느 이벤트에도 없는 파라미터에는 `사전에 없음` 태그를 붙인다. 항목이 하나도 없으면 "GA에 등록된 파라미터가 없어요"를 보여 준다.

**CSV**

지금 걸러진 이벤트를 내보낸다. `CSV 받기` 버튼은 판정이 끝난 뒤에만 보여 준다. 판정 전의 목록을 내보내면 횟수가 비고 상태가 전부 `정상`으로 적힌다. 열은 이벤트 이름, 한글 라벨, 구분, 상태, 횟수, 사람 수, 설명, 파라미터(이름을 쉼표로 이음)다. 파일 이름은 `parfait-event-dictionary-<시작일>_<종료일>.csv`다.

### URL 상태

| key | 값 | 예 |
|-----|----|----|
| `q` | 검색어 | `q=purchase` |
| `status` | `unknown`, `missing`, `partial`, `undocumented` | `status=unknown` |
| `event` | 펼친 이벤트 이름 하나 | `event=purchase_done` |

`event`를 URL에 두므로 "이 이벤트 좀 봐줘"를 링크로 보낼 수 있다. 한 번에 하나만 펼친다.

`event`가 가리키는 이벤트의 처리:

- 링크나 스트림의 `사전에서 보기`로 열린 이벤트는 판정이 끝났을 때, 그리고 맨 위의 임시 행이 정렬된 자리로 옮겨질 때 그 행이 보이도록 스크롤한다(움직임 효과 없음). 목록에서 직접 펼친 행에는 스크롤하지 않는다.
- `event`가 가리키는 이벤트가 합친 목록에 없고 오늘 관측이 이 화면을 열기 전에 받아 둔 값이면, 오늘 관측을 한 번 더 조회한다. 스트림에서 방금 본 이벤트가 60초 안에 받아 둔 값 때문에 기록 없음으로 남지 않게 하려는 것이다.
- 지금 필터에 걸러진 이벤트면, 그 행을 목록 맨 위에 "필터와 상관없이 보여요"라는 말과 함께 보여 준다. 이 행은 CSV와 상태별 개수에는 넣지 않는다.
- 카탈로그에도 없고 들어온 기록도 없는 이름이면, 같은 자리에 임시 행을 만든다. 내용은 "이 기간과 최근 30분에 들어온 기록이 없어요"와 `카탈로그 항목 복사` 버튼이다. 관측을 아직 받는 중이면 스켈레톤을 보여 주고, 받은 뒤에 다시 판정한다. 기간 관측이 실패했거나 기간이 잘못됐으면 "수집 현황을 확인하지 못해서 이 이벤트의 기록을 알 수 없어요"를 쓰고 복사 버튼은 두지 않는다. 확인하지 못한 것을 없다고 말하면 안 된다. 오늘 관측만 실패했으면 "이 기간에 들어온 기록이 없어요. 오늘 들어온 이벤트는 확인하지 못했어요."라고 쓴다.
- `카탈로그 항목 복사`는 이름이 GA 이벤트 이름 형식(영문자로 시작, 영문자·숫자·밑줄, 40자 이하)일 때만 보여 준다. `event`는 누구나 주소에 적을 수 있는 값이고, 복사된 코드는 사람이 카탈로그 파일에 붙여 넣는다.
- 누른 버튼이 화면에서 사라지는 동작에는 포커스가 갈 곳을 정한다: 걸러진 행을 접으면 목록의 첫 행(목록이 비었으면 고른 상태 버튼), `필터 지우기` 뒤에는 검색창. `다시 시도`는 조회하는 동안 자리를 지키고, 성공하면 검색창으로 간다.
- 사용자가 상태 버튼이나 검색어를 바꾸면 `event`를 지운다. 필터를 바꿨는데 걸러지지 않는 행이 남아 있으면 혼란스럽다.

### 상태별 화면

- 기간 관측 조회 중: 카탈로그 내용은 바로 보여 주고 횟수 열만 스켈레톤이다. 카탈로그는 번들에 있어서 기다릴 것이 없다.
- 기간 관측 실패: 카탈로그 내용은 그대로 두고, 표 위에 "수집 현황을 불러오지 못했어요"와 `다시 시도`를 보여 준다. 횟수 열은 `—`다.
- 기간이 잘못됨(`periodError`): 기간 관측을 조회하지 않는다. 횟수 열은 `—`이고 표 위에 "기간을 다시 골라 주세요"를 보여 준다. 기간 오류 문구 자체는 셸의 기간 필터가 보여 준다.
- metadata 실패: `GA에 등록된 파라미터` 카드에만 오류를 보여 준다. 파라미터의 `GA 등록됨` 태그는 붙이지 않는다.
- 필터 결과 없음: "조건에 맞는 이벤트가 없어요"와 `필터 지우기`. `q`, `status`, `event`를 지운다.

### 모바일과 접근성

- 960px 미만에서는 `구분` 열을 빼고 펼친 내용에서 보여 준다. 이벤트 칸은 줄바꿈을 허용한다.
- 상태 버튼 다섯 개는 좁은 화면에서 줄바꿈된다. 가로 스크롤로 숨기지 않는다.
- 펼치기 버튼, 상태 버튼, `카탈로그 항목 복사`는 누르는 영역이 44px 이상이다.
- 검색창에는 보이는 라벨을 두고 글자 크기는 16px 이상이다.
- 복사 결과("복사했어요")는 `role="status"`로 알린다.

## 4. 이벤트 카탈로그

`src/admin/ga/eventCatalog.ts`를 새로 만든다. 사전, 스트림, 기존 `많이 한 행동` 화면이 모두 이 파일을 읽는다.

```ts
export type EventPlatform = 'Android' | 'iOS'

export type EventParam = {
  name: string
  type: 'string' | 'number' | 'boolean'
  description: string
}

export type CatalogEvent = {
  name: string
  /** 화면에 쓰는 한글 이름. 비어 있으면 원래 이름을 쓴다. */
  label: string
  description: string
  /** auto: Firebase가 자동으로 수집한다. app: 앱 팀이 구현한다. */
  kind: 'auto' | 'app'
  params: readonly EventParam[]
  /** 이 이벤트를 보내야 하는 플랫폼. 생략하면 ALL_PLATFORMS다. */
  platforms?: readonly EventPlatform[]
}

export const ALL_PLATFORMS: readonly EventPlatform[]   // ['Android', 'iOS']
export const EVENT_CATALOG: readonly CatalogEvent[]
export function findEvent(name: string): CatalogEvent | undefined
```

- 지금 `eventLabels.ts`에 있는 자동 수집 이벤트 10개를 `kind: 'auto'`로 옮긴다. 설명은 Firebase 문서의 뜻을 해요체로 한 줄씩 쓴다.
- 앱 정의 이벤트는 비워 둔다. 앱 팀의 정의 문서가 오면 이 파일에 옮겨 적는다. 그때까지 앱 이벤트는 사전에서 `사전에 없음`으로 보인다. 의도한 동작이다.
- `EventPlatform`의 값은 GA `platform` 측정기준의 값과 같은 문자열이다.
- `eventLabels.ts`의 `eventLabel(name)`은 시그니처를 그대로 두고 카탈로그를 읽도록 바꾼다. `label`이 비어 있는 항목은 등록되지 않은 것으로 돌려준다. `많이 한 행동` 화면은 손대지 않는다.

테스트로 지키는 규칙: 이벤트 이름이 중복되지 않는다. 한 이벤트 안에서 파라미터 이름이 중복되지 않는다. 이름은 GA 규칙(영문자로 시작, 영문자·숫자·밑줄, 40자 이하)을 지킨다.

## 5. 공용 코드 변경

고치는 공용 파일은 아래뿐이다. 기반의 "고치지 않는 파일" 7개에 들지 않는다. 묶음 1은 GA를 쓰지 않으므로 `ga/` 아래 변경과 겹치지 않는다. `NavContext.tsx`는 묶음 1이 읽기만 하는 파일이다.

### `src/admin/ga/types.ts`

- `RunRealtimeReportRequest`에 `returnPropertyQuota?: boolean`과 `orderBys?: OrderBy[]`를 넣는다.
- `PropertyQuota`에 `tokensPerHour`, `tokensPerProjectPerHour`, `concurrentRequests`, `serverErrorsPerProjectPerHour`를 선택 필드로 넣는다. 모양은 `tokensPerDay`와 같다.
- `Metadata`, `DimensionMetadata`, `MetricMetadata` 타입을 넣는다. 필요한 필드는 `apiName`, `uiName`, `description`, `customDefinition`이다.

### `src/admin/ga/client.ts`

- `runRealtimeReport`가 `returnPropertyQuota: true`를 붙여 보낸다. 응답의 `propertyQuota`는 호출한 쪽이 읽는다. 기존 테스트 "runRealtimeReport does not add returnPropertyQuota"(`client.test.ts`)는 반대 동작을 확인하므로 새 동작에 맞게 바꾼다.
- realtime 응답의 quota로는 `onQuota`를 부르지 않는다. `onQuota`는 푸터의 "오늘 조회 가능량"을 채우는데, 그 숫자는 일반 조회 한도다.
- `getMetadata()`를 넣는다. `GET {BASE_URL}/{propertyId}/metadata`를 부른다. 지금 `post` 함수가 가진 토큰 확인, 네트워크 오류 처리, 오류 응답 분류를 HTTP 메서드를 받는 함수 하나로 빼서 POST와 GET이 같이 쓴다.

기존 `지금 접속 중`과 `한눈에 보기`의 realtime 호출은 요청에 필드 하나가 늘 뿐 동작이 같다.

### `src/admin/ga/eventLabels.ts`

§4대로 카탈로그를 읽게 바꾼다.

### `src/admin/menu/NavContext.tsx`

`setMenu`가 두 번째 인자로 페이지 파라미터를 받는다.

```ts
setMenu(menu: MenuId, params?: Readonly<Record<string, string>>): void
```

- `params`를 주면 새 메뉴의 페이지 파라미터로 쓴다. 생략하면 지금처럼 비운다.
- 예약어(`menu`, `period`, `start`, `end`)가 key에 있으면 개발 모드에서 경고하고 그 key를 버린다.
- 이미 그 메뉴에 있을 때 `params`를 주면, 방문 기록을 새로 만들지 않고 페이지 파라미터를 그 값으로 바꾼다. `params` 없이 같은 메뉴를 부르면 지금처럼 아무 일도 하지 않는다.
- `urlState.ts`는 고치지 않는다. `toSearch`가 이미 페이지 파라미터를 URL에 쓴다.

이 변경은 다른 묶음도 쓸 수 있다(예: 링크 허브에서 특정 화면을 필터와 함께 열기).

### 고치지 않는 것

- `src/admin/hooks/useReports.ts`: 새 훅은 각 페이지 폴더에 둔다. 묶음마다 이 파일에 훅을 더하면 병렬 작업끼리 겹친다. 대신 페이지 폴더의 query key는 메뉴 id로 시작한다(`['event-stream']`, `['event-dictionary', ...]`). 기존 key(`'realtime'`, `'events'` 등)와 겹치지 않게 하기 위한 규칙이다.
- `src/admin/components/DataTable.tsx`: 두 화면의 표는 행 강조, 펼치기, 행 고정이 필요해서 `DataTable`의 모양(셀 값만 받음, 행 key가 순번)에 맞지 않는다. 각 페이지 폴더에 표 컴포넌트를 두고, 모양은 기존 `adm-table` 클래스를 그대로 써서 맞춘다.
- `src/admin/components/CardState.tsx`: 빈 상태는 각 화면이 직접 그린다(§2, §3의 상태별 화면).

## 7. 이번에 하지 않는 것

- **화면에서 사전 편집**: 저장할 곳이 없다. `카탈로그 항목 복사`와 PR로 대신한다.
- **스트림에서 파라미터 값 보기**: Realtime API가 지원하지 않는다.
- **QA하는 사람별로 이벤트 가르기**: 앱이 QA용 사용자 속성을 보내고 그것을 GA에 사용자 범위 커스텀 측정기준으로 등록하면, `customUser:<이름>`으로 스트림을 좁힐 수 있다. 앱 쪽 작업이 먼저라서 후속 작업으로 둔다.
- **앱 정의 이벤트 채우기**: 앱 팀의 정의 문서가 온 뒤에 한다.
- **푸터 "오늘 조회 가능량"의 계산 오류 고치기**: `src/admin/hooks/useGa.ts`의 `quotaPercent`가 `remaining / (consumed + remaining)`으로 계산한다. `consumed`는 요청 하나가 쓴 양이라서 이 값은 한도가 거의 바닥날 때까지 100%에 가깝다. 기존 버그이고 이 묶음의 화면과 무관하므로 기반 후속 작업으로 따로 고친다.

## 8. 실제 호출로 확인할 것

토큰이 브라우저 메모리에만 있어서 명령줄에서는 확인할 수 없다. 스트림 화면의 조회가 붙은 뒤, 사용자가 `npm run dev`로 화면을 열어서 확인한다.

이를 위해 스트림 화면은 개발 모드(`import.meta.env.DEV`)에서만 상태 줄 아래에 진단 한 줄을 보여 준다. 내용은 직전 요청이 쓴 토큰 수(`consumed`), 세 한도의 남은 양, 받은 행 수다. 빌드 결과에는 들어가지 않는다.

| 확인할 것 | 방법 | 결과에 따라 바꾸는 것 |
|-----------|------|------------------------|
| 반영 지연 | 앱에서 이벤트를 보내고 화면에 나타날 때까지 잰다 | 지연이 10초를 넘으면 기본 주기를 그 값에 맞춘다. 5초마다 물어도 새 데이터가 없기 때문이다. |
| 요청당 토큰 비용 | 진단 줄의 값을 읽는다 | 기본 주기로 한 시간 쓴 양이 14,000 토큰의 절반을 넘으면 기본 주기를 늦춘다. 그래도 넘으면 `appVersion` 측정기준을 빼고 앱 버전 필터를 없앤다. |
| metadata | 사전 화면의 파라미터 카드를 본다 | 응답 모양이 §3과 다르면 파싱을 맞춘다. |

확인한 값과 그에 따라 정한 상수는 이 문서의 이 장에 적는다.

## 9. 테스트

**단위**

- `eventCatalog`: §4의 규칙, `findEvent`, `eventLabel`의 기존 동작
- `client`: realtime 요청에 `returnPropertyQuota`가 붙는지, realtime quota로 `onQuota`를 부르지 않는지, `getMetadata`의 메서드와 URL과 오류 분류
- `NavContext`: `setMenu(id, params)`가 URL에 파라미터를 쓰는지, 예약어를 버리는지, 같은 메뉴에서의 동작, `params`가 없을 때 기존 동작
- 스트림 `report`: 요청 모양, fixture 파싱, 빈 값과 `(not set)` 합치기, 필터별 합계, `방금`/`5분`/`30분` 계산, 추이 30칸 채우기, 직전 갱신과의 비교(필터를 바꿔도 거짓 `▲`가 없는지 포함), 잘림 판정
- `pollPolicy`: 멈춤 표와 평소 주기 표의 모든 줄, 줄 사이의 우선순위, 실패 시 `max` 규칙과 60초 상한, 남은 한도 계산(항목이 빠진 경우 포함)
- 사전 `report`: 요청 모양, fixture 파싱, metadata의 `dimensions[]`와 `metrics[]`에서 `customEvent:` 고르기
- `dictionary`: §3 상태 표의 모든 줄, 자동 수집 예외, 기간 관측이 없을 때 판정하지 않는 것, 오늘 관측만 있는 이벤트, 기본 대상 플랫폼, 정렬
- `SearchField`: 300ms 뒤 쓰기, 포커스 잃음과 Enter, 한글 조합 중 쓰지 않기, 바깥에서 값이 바뀌면 다시 읽기

**페이지**

- 스트림: 검색과 필터, 지켜보기 고정과 0건 행, 지켜보는 행이 검색어를 무시하는지, 강조가 60초 남고 사라지는지, 비교 기준이 오래되면 강조하지 않는지, 일시정지와 다시 시작, 가짜 타이머로 주기 확인, 탭이 다시 보일 때의 조회(일시정지 중에는 조회하지 않음), 조작이 돌아왔을 때의 조회, URL 파라미터 읽고 쓰기, 빈 상태와 오류 상태, 갱신 실패 때 표가 남는지, `사전에서 보기`가 파라미터와 함께 이동하는지
- 사전: 상태 버튼과 개수, 관측 전 `—` 표시, 검색, 펼치기와 `event` 파라미터, 걸러진 이벤트와 기록이 없는 이름의 `event` 처리, 필터를 바꾸면 `event`가 지워지는지, 복사 버튼, CSV 내용, 기간 관측 실패 때 카탈로그가 남는지, 오늘 관측 실패 안내, 기간 오류, metadata 실패가 카드에만 보이는지

**확인 명령**

`npm run typecheck`, `npm test`, `npm run build`가 모두 통과해야 한다. 외부 주소를 새로 쓰지 않으므로 CSP 조각은 없다. 그래도 `npm run build && npm run preview`에서 두 화면을 열어 CSP 위반이 없는지 본다.

## 10. 기반 규칙 점검

| 규칙 | 이 묶음 |
|------|---------|
| 메뉴 `id`가 유일하다 | `event-stream`, `event-dictionary`. 기존 6개와 겹치지 않는다. 다른 묶음 스펙은 아직 없다. |

| CSS 클래스 접두사 | `adm-event-stream-`, `adm-event-dictionary-`. 이 규칙을 검사하는 코드는 없으므로 리뷰에서 눈으로 확인한다. |
| 고치지 않는 파일 7개 | 고치지 않는다. `NavContext.tsx`는 그 목록에 없다. |
| 의존성 추가 | 없다. |
